QUICK REFERENCE

Study Notes & Cheatsheets

A working collection of Cisco IOS and host commands that I regularly use while configuring, verifying and troubleshooting lab networks.

These notes are not intended to replace understanding of the underlying technologies. They provide a quick reference for commonly used commands while working through practical networking labs.

Core verification commands

A small number of commands appear repeatedly throughout almost every Cisco lab because they provide a quick picture of the device state. 

show ip interface brief
show interfaces status
show interfaces description
show running-config
show vlan brief
show ip route
show ip ospf neighbor
show ip route ospf
show running-config | section router ospf
show mac address-table
show cdp neighbors

show ip interface brief

Provides a concise view of interface addressing and interface/protocol status.

show interfaces status

Useful on switches for quickly reviewing port state, VLAN assignment, duplex and speed information.

show interfaces description

Displays interface descriptions alongside interface state, making sensible interface descriptions particularly useful during troubleshooting.

show running-config

Displays the currently active configuration and is one of the main sources of evidence when comparing intended configuration with actual device state.

show vlan brief

Provides a quick view of VLANs and access-port membership.

show ip route

Displays the IPv4 routing table and the routes currently available to the device.

show ip ospf neighbor

Displays OSPF neighbour relationships and their current state. This is one of the quickest ways to confirm whether an expected OSPF adjacency has formed.

show ip route ospf

Filters the IPv4 routing table to routes learned through OSPF and is useful for verifying that remote networks are actually being advertised and installed.

show running-config | section router ospf

Isolates the OSPF portion of the running configuration, making it easier to compare neighbouring routers and identify configuration mismatches.

show mac address-table

Displays MAC addresses learned by the switch and the interfaces through which they are reachable.

show cdp neighbors

Displays neighbouring Cisco devices discovered through Cisco Discovery Protocol and can be useful when establishing how devices are physically connected.

Saving and managing configuration

Save the active configuration

copy running-config startup-config

Copies the active running configuration into startup configuration so it can be restored after a reboot.

The shorter traditional command is:

write memory

Erase startup configuration

erase startup-config

or on platforms that support it:

write erase

These commands remove the saved startup configuration. A reload is normally required afterwards if the objective is to restart the device without the saved configuration.

Reload the device

reload

Interface configuration

Select an interface

interface gigabitEthernet0/1

Enters interface configuration mode for the selected physical or logical interface.

Add an interface description

description Uplink-to-Router

Clear descriptions make later troubleshooting significantly easier, particularly once a topology contains several inter-device links.

Enable an interface

no shutdown

Administratively enables the interface.

Example

interface gigabitEthernet0/1
 description Uplink-to-Router
 no shutdown
SVI STATUS

Creating a VLAN does not necessarily mean its switched virtual interface will immediately become up/up. In a typical Layer 2 switch environment, the VLAN must exist and normally needs at least one active Layer 2 port in that VLAN and in a forwarding state.

OSPF configuration and troubleshooting

These commands are useful when configuring OSPF, checking neighbour relationships and determining whether expected networks are being advertised and learned correctly.

Display OSPF neighbours

show ip ospf neighbor

Displays OSPF neighbour relationships and their current state. A successfully established adjacency should normally reach the FULL state.

Display OSPF-enabled interfaces

show ip ospf interface brief

Provides a concise view of interfaces participating in OSPF, including their process, area and interface state.

Inspect detailed OSPF interface information

show ip ospf interface

Displays detailed OSPF information for participating interfaces, including area membership, timers, network type and neighbour-related information.

Display OSPF-learned routes

show ip route ospf

Filters the routing table to routes learned through OSPF. This is particularly useful after neighbour relationships have formed because a FULL adjacency does not necessarily mean every required network is being advertised.

Review routing protocol information

show ip protocols

Displays information about active routing protocols, including routing processes, passive interfaces and the networks currently being matched by routing protocol configuration.

Display the OSPF section of the running configuration

show running-config | section router ospf

Isolates the OSPF configuration from the complete running configuration, making it easier to compare neighbouring routers when troubleshooting.

Basic OSPF configuration

router ospf 1
 router-id 1.1.1.1
 network 10.0.12.0 0.0.0.3 area 0

Creates OSPF process 1, assigns a router ID and enables OSPF on interfaces matched by the network statement. The OSPF process ID is locally significant and does not need to match neighbouring routers.

Configure a passive interface

router ospf 1
 passive-interface gigabitEthernet0/0

Prevents OSPF Hello packets from being sent on the selected interface while still allowing its connected network to be advertised through OSPF when that network is included in the routing process.

Restore OSPF neighbour formation on an interface

router ospf 1
 no passive-interface gigabitEthernet0/2

Removes the passive setting so that OSPF Hello packets can once again be exchanged and a neighbour relationship can form.

OSPF Hello debugging

debug ip ospf hello
undebug all

Displays OSPF Hello activity in real time and can help identify neighbour formation problems. Debugging should be disabled when the required evidence has been collected.

OSPF TROUBLESHOOTING

A FULL OSPF neighbour relationship confirms that an adjacency has formed, but it does not prove that every required network is being advertised. Check both show ip ospf neighbor and show ip route ospf when verifying the final network state.

Device management

Default gateway on a Layer 2 switch

ip default-gateway 192.168.1.1

Configures the gateway used by a Layer 2 switch for management traffic destined beyond its local subnet.

Console configuration

line console 0

Enters configuration mode for the console line.

VTY configuration

line vty 0 4

Selects a range of virtual terminal lines used for remote management sessions.

Idle session timeout

exec-timeout 10 0

Disconnects an idle EXEC session after 10 minutes and 0 seconds.

Passwords and local authentication

Local user account

username admin secret <password>

Creates a local username with a protected secret suitable for use with local authentication.

Use the local user database

login local

Configures the relevant line to authenticate against the device's local username database.

Password encryption

service password-encryption

Obscures supported plain-text passwords in the configuration using Cisco's reversible Type 7 encryption.

It prevents casual reading of passwords in the configuration but should not be treated as strong cryptographic protection.

SSH configuration

Common commands used while configuring SSH management include: 

ip domain name example.local
username admin secret <password>
crypto key generate rsa
ip ssh version 2

line vty 0 4
 login local
 transport input ssh

ip domain name

Defines a domain name for the device. Together with the hostname, this is used when generating RSA keys on Cisco IOS devices.

crypto key generate rsa

Generates the RSA key pair required by the IOS SSH server.

ip ssh version 2

Configures the device to use SSH version 2.

transport input ssh

Restricts incoming remote-management sessions on the selected VTY lines to SSH.

MAC address table

Display learned MAC addresses

show mac address-table

Clear dynamically learned addresses

clear mac address-table dynamic

Removing dynamic entries can be useful during troubleshooting when testing how a switch relearns connected devices.

Useful host troubleshooting commands

Troubleshooting does not stop at the router or switch. Host-side tools are often needed to establish whether addressing, DNS or end-to-end connectivity is working correctly.

ipconfig

ipconfig
ipconfig /all

Displays Windows interface addressing including IP address, subnet mask, default gateway and DNS information.

arp -a

arp -a

Displays entries in the host's ARP cache.

ping

ping 192.168.1.1

Sends ICMP Echo Requests to test IP reachability to another device.

tracert

tracert 8.8.8.8

Displays the Layer 3 path towards a destination by observing the routers encountered along the route.

nslookup

nslookup example.com

Queries DNS and is useful when distinguishing a name-resolution problem from a general connectivity problem.

getmac

getmac

Displays MAC addresses associated with Windows network interfaces.

netstat

netstat -ano

Can display active connections, listening ports and associated process information.

tasklist

tasklist

Displays processes currently running on a Windows system.

taskkill

taskkill /PID <process-id>

Terminates a Windows process using its process ID or other selection criteria.

How I use the notes

Configuration

Quick references reduce unnecessary context switching while I am building a lab.

Verification

Show commands provide the evidence needed to establish whether the configuration is actually working.

Troubleshooting

Commands are grouped around questions about interface state, Layer 2 behaviour, addressing, routing and host connectivity.

Recall

Repeated practical use gradually turns frequently required commands from reference material into working knowledge.

A USEFUL DISTINCTION

The aim is not to memorise every Cisco IOS command.

The more important skill is knowing what information I need from the network, which command can provide that evidence and how to interpret the result.
